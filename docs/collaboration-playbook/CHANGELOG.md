# Changelog

All notable changes to the Collaborative Architecture and Design Playbook are recorded here.

## [0.8.0] - 2026-07-24

### Added

- Product Support Manager personality specification grounded in DoDI 5000.91, DoDI 5000.87, and Product Support Manager Guidebook themes: affordable readiness, lifecycle support, the 12 IPS elements, decision-quality data, and continuous improvement.

## [0.7.0] - 2026-07-24

### Added

- Chief Engineer personality specification for technical baseline control, requirements allocation, interface/integration discipline, verification, risk disposition, and release readiness.

## [0.6.0] - 2026-07-24

### Added

- Chief Architect personality specification for enterprise synthesis, target-state stewardship, architectural decision framing, quality attributes, exceptions, and transition roadmaps.

## [0.4.0] - 2026-07-24

### Added

- Ruthless QA Evaluator personality specification with evidence-based finding criteria, severity guidance, interface/failure-mode scrutiny, and constructive review output template.

## [0.3.0] - 2026-07-24

### Added

- Default Connected Collaborator personality specification for warm, continuous, evidence-led architecture and design collaboration.

### Changed

- Established the personality specification as the default interaction style while retaining protocol, authority, and verification safeguards.

## [0.2.0] - 2026-07-24

### Added

- GitHub document-control standard requiring a dedicated repository per project, protected baseline branch, working branches, pull requests, reviews, and merges.
- GitHub-specific merge gate, ADR/issue linkage, and release-artifact provenance requirements.

### Changed

- Clarified that a documentation baseline is established only after the reviewed pull request is merged to the repository default branch.
- Updated session templates and checklists with GitHub repository, branch, pull-request, and merged-SHA fields.

## [0.1.0] - 2026-07-24

### Added

- Initial collaboration protocol defining roles, brainstorming, recommendation challenge, decision acceptance, correction, and commit execution.
- Evidence and traceability model with context-handoff requirements.
- Documentation governance, changelog, ADR, and quality-gate practices.
- Artifact delivery and verification procedure, including package-manifest requirements.
- Reusable session, recommendation, commit, handoff, ADR, and checklist templates.
